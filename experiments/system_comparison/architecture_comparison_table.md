# Table 2: Architecture Comparison

This table compares the architectural properties, communication protocols, governance, and fault-handling mechanisms across the four examined systems.

| Dimension | RetailOps | Flowr | WorkflowLLM | Agentic Inventory Replenishment | Comparability Note |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Workflow Topology** | Explicit LangGraph StateGraph DAG with deterministic node execution guards | Central reasoning LLM and dynamic multi-agent coordination reported in literature | Generative API call graphs generated dynamically by fine-tuned LLM | Autonomous multi-agent coordination loops with reinforcement learning | Different workflow execution paradigms |
| **Inter-Service Protocol** | Model Context Protocol (FastMCP) over STDIO JSON-RPC 2.0 with persistent session pooling | Model Context Protocol (MCP) utilized as an interface to databases, tools, and UI | Standard REST / JSON APIs integrated into prompt fine-tuning dataset | Custom internal agent messaging and environment simulation interfaces | RetailOps and Flowr share MCP; WorkflowLLM uses REST APIs |
| **Process Boundaries & Isolation** | Separate MCP service processes communicating through STDIO; verified process cleanup | The reviewed sources did not establish whether Flowr uses specific OS subprocess isolation | In-process model generation or simulated benchmark execution environments | Not established whether specific OS subprocess isolation is used | Evaluated experimentally in RetailOps; not established in other sources |
| **Service Decoupling** | High: Independent OS subprocesses with zero shared memory or global state variables | High: Cognitive decomposition into autonomous domain-specialized agent units | Low to Moderate: Integrated into LLM tool-calling prompt contexts | Moderate: Decentralized agent roles | Different levels of modular abstraction |
| **Service Replacement** | Experimentally evaluated in Task 04 with 0 LOC changes across existing services | Modular agent replacement discussed conceptually, but empirical replacement experiments not reported | Model weights or API endpoints can be updated; replacement effort not explicitly evaluated | Not reported in the reviewed source | Evaluated experimentally in RetailOps; asymmetric literature evidence |
| **Extensibility** | Experimentally evaluated in Task 08: 5th service added with 0 LOC modified in existing services | Described as a domain-independent blueprint; quantitative extension effort not reported | Extensible via fine-tuning or in-context learning over new APIs | Not reported in the reviewed source | Evaluated experimentally in RetailOps; conceptual in Flowr |
| **Human Supervision** | Not implemented as a full HITL interactive approval system; outputs store-manager explanations | Reported as part of Flowr's design via an MCP-enabled supervisory interface | Autonomous API execution without mandatory interactive human-in-the-loop gates | Autonomous ordering with managerial oversight noted in deployment context | Different operational scopes and design goals |
| **Governance & Validation** | Programmatic validation guards, schema checking, and explicit failure states (`failed_enrichment`) | Multi-layer Pre-Action Governance Reasoning Loop (PAGRL) via an MCP governance server | Heuristic constraint checking and prompt validation during tool execution | Heuristic constraint checking within reinforcement learning environment | Different governance philosophies |
| **Fault Handling & Cleanup** | Experimentally evaluated across 6 failure modes; verified 100% downstream abort and psutil cleanup | Proactive exception prevention via pre-action policy reasoning; human escalation | Execution error handling and dynamic re-planning on benchmark tasks | Heuristic error recovery within replenishment simulation | Evaluated experimentally in RetailOps; different recovery mechanisms |
| **Public Reproducibility** | Fully reproducible local repository with end-to-end runnable tests and raw JSONL logs | Published preprint (arXiv:2604.05987); complete code and enterprise data not established | Open-source dataset (WorkflowBench) and code repository on GitHub | Published preprint (arXiv:2511.23366); standalone code repository not established | Contrasting artifact availability |
